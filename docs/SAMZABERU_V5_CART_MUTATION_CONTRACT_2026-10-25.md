# СамЗаберу API V5 — изменение существующих позиций корзины

**Дата:** 2026-10-25  
**Статус:** код в feature-ветке, V5 AUTH OFF, production НЕ развёрнут, интеграционные транзакции не проверены.

## Для разработчика приложения

Базовый публичный домен: **https://evrasia.rest**. Все запросы передаются по HTTPS, с `Content-Type: application/json`. Используется только access JWT V5, выданный работающей серверной MFA/доверенной сессией; JWT V4 недопустим.

### 1. Установить количество существующей позиции

`POST https://evrasia.rest/api/v5/cart/items/quantity`

Пример тела:

```json
{"access_token":"<V5 access JWT>","item_id":401,"quantity":2}
```

`item_id` — **ID строки корзины**, полученный от `GET /api/v5/cart` (поле `items[].id`), а **не ID товара**. `quantity` — целое от 1 до 1000; для удаления нужно вызвать отдельный маршрут. Значение 0 запрещено.

Ответ после подтверждённой транзакции:

```json
{"item":{"item_id":401,"quantity":2}}
```

### 2. Удалить существующую позицию

`POST https://evrasia.rest/api/v5/cart/items/remove`

Тело:

```json
{"access_token":"<V5 access JWT>","item_id":401}
```

Ответ после подтверждённой транзакции:

```json
{"item":{"item_id":401,"removed":true}}
```

После обеих операций приложение может повторно запросить `GET /api/v5/cart` для актуальной итоговой стоимости; **цены не устанавливаются приложением**.

### Ответы и безопасность

- `200` — изменение подтверждено и завершено.
- `400 invalid_request` — недопустимые ключи/типы/количество/ID.
- `401 authentication_failed` — некорректный либо не прошедший сильную V5-сессию access JWT.
- `403 secure_transport_required` — не подтвержден HTTPS транспорт.
- `405 method_not_allowed` — неверный HTTP метод.
- `503 v5_unavailable` — V5 cart mutator ещё не подключён в конфигурации сайта.
- `503 temporarily_unavailable` — ошибка защищённого сохранения или невозможность подтвердить результат; не считать операцию успешной.

Клиент **не может** задавать `USER_ID`, `FUSER_ID`, цену, валюту, оплату, ID ресторана или `product_id` через эти два метода. Для добавления **нового товара** отдельного API V5 пока нет — подмена `item_id` на `product_id` недопустима.

## Реализация на сервере

- `V5CartMutationRequest` — строгая проверка JSON и типа операции.
- `V5AuthHttpHandler` + `V5RouteMap` + `V5HttpTransportBoundary` — два явных маршрута с HTTPS, ограничением размера запроса и `Cache-Control: no-store`.
- `V5MySqlCartMutation` и `V5MySqlStrongSessionStore::changeCartForAccess` — сильная V5 JWT-сессия, блокировка пользователя, проверка текущего AUTH_EPOCH, native MFA coverage, ревокации и завершающей транзакции.
- `V5BitrixNativeCartMutator` — единственный нативный D7 обработчик существующих basket line IDs: проверяет server-owned FUSER, выбирает принадлежащую ему строку корзины, выполняет только QUANTITY/update или delete, делает `Basket::save()` и повторно читает записанное состояние через то же соединение Bitrix.
- `V5NativeCartMutationReadinessPort` — **обязательное отдельное разрешение от сайта**, без реализации по умолчанию. Код отказывает до D7, если строгая FPM-native транзакция, доступность native event hooks и безопасность сохранения не подтверждены.
- Public/pilot composition принимают **необязательный** `cartMutator`; отсутствие параметра означает HTTP 503, что сохраняет текущую выключенную конфигурацию.

## Тестирование и ограничения

GitHub Actions: https://github.com/juvantusik/Evrasia_AI_bot/actions/runs/40215020972 — **SUCCESS**, 412/412 mock-only тестов (375 предыдущих + 37 новых). Проверены строгие поля тела, отказ пользовательским ID/FUSER/цене, отсутствие V4 JWT, транспорт, обработка ответа и режим OFF. Нативная транзакция Bitrix D7 и реальный результат изменения корзины **НЕ проверялись**.

**Важно:** эти маршруты ещё не запущены на production. Перед включением требуется site-level подтверждение общего транзакционного контура D7/V5 и side effects `Basket::save()`, а также штатный V5 release readiness. API V4 не меняем, V5 AUTH остаётся OFF, никаких синтетических аккаунтов, реальных заказов и отправок в колл-центр.

Маршрут оформления заказов остаётся: СамЗаберу → API V5 → Bitrix → **существующий канал передачи в колл-центр**. Внутреннюю работу колл-центра не исследуем.
