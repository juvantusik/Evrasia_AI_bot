# API V5 — реальные документы регистрации из действующего Bitrix

**Публичный адрес для клиентов:** `GET https://evrasia.rest/api/v5/legal/registration-documents`.

**Статус:** реализовано в ветке `feature/samzaberu-api-v5-auth-contract`, **не объявлять доступным на публичном production до подтверждённого выката и внешней HTTP-проверки**. Это следующий перенос из зарегистрированного V4 `GET /legal/registration-documents`; точное равенство старому V4 JSON **не подтверждено** и не предполагается.

## Реальное поведение новой V5-ручки

- Возвращает **актуальные версии обязательной оферты и согласия на обработку персональных данных**, а также необязательный маркетинговый документ, если он находится в текущем каталоге. В новом V5 HTTP методе используется **тот же** `V5BitrixPublicLegalCatalog::read()` и `V5LegalConsentContract::publicDocuments()`, что уже обеспечивают публичный `GET /api/v5/legal/consents`. Никаких новых SQL-запросов, копий юридического текста или схем расчёта.
- Формат V5: `{"documents":[{"code":"...","type":"offer","title":"...","required":true,"format":"url|text|html","content":null,"url":"https://.../legal/..."}]}`. В реальном результате присутствуют 2–3 документа; поля и значения извлекаются из **текущего** `b_consent_agreement`, а не из пользовательского ввода или списка устаревших кодов. Приведённая форма — схема, а не данные пользователя.
- 200 при успешно подтверждённом актуальном наборе; 503 `{"error":"temporarily_unavailable"}` при отказе чтения/невалидном каталоге; 503 `{"error":"v5_unavailable"}` если native provider не установлен в защищённой композиции. Ошибочные методы, query-аргументы, тела и не-HTTPS запросы отвергаются в V5 transport. Сайт в production не обязан предоставлять маршрут до выката исходника.
- Операция **не требует JWT и не записывает согласие**. Выбор актуальных кодов клиентом затем проверяется через `POST /api/v5/legal/consents/validate`; юридическую фиксацию можно осуществлять только внутри ещё не выпущенного согласованного регистрационного/подписного native flow.
- Никаких вызовов V4 PHP-контроллеров/токенов, `CUser::Add`, SMS, создания нового аккаунта или записей в `b_consent_user_consent`.
- Ссылка на юридическую страницу в существующем каталоге может сохранять хост `evrasia.spb.ru` — это **адрес текста юридического документа**, он не подменяет основной публичный API `evrasia.rest`. Без подтверждения содержимого текущих записей `b_consent_agreement` ссылки не переписываются.

## Исходники и проверки

Внесены изменения в `src/V5RouteMap.php`, `src/V5AuthHttpHandler.php`, `src/V5HttpTransportBoundary.php`, `src/V5ParallelHttpEntry.php` и реальный `api/v5/router.php`. Последний содержит отдельную **анонимную read-only ветку**, работающую через уже внедрённый в сайт источник Bitrix legal, без включения приватного V5 AUTH. Обратная совместимость существующего GET `/legal/consents` сохраняется.

Регрессии `V5PublicContractsTest.php`: текущие документы равны общему реальному каталогу, JWT не проверяется и не выпускается, некорректный метод/URI/тело/контент блокируются, отключённый/missing reader ->503, ошибка каталога ->503, публичный GET не считывает тело запроса. `V5RouteMapTest.php` проверяет регистрацию пути; `V5V4ReplacementGateTest.php` проверяет, что маршрут можно считать **feature-only**, но никак не принятым production. CI syntax lint дополнен реальным router. До успешного CI выводы об offline PASS делать нельзя.

## Для разработчика «СамЗаберу»

Вызывать `GET /api/v5/legal/registration-documents` без bearer, показывать `required` документы, предоставлять выбор опционального `marketing` и отправлять **полученные от сервера** `code` в `POST /api/v5/legal/consents/validate`. Положительный ответ `valid:true` не является юридически сохранённым согласием и не создаёт пользователя. Перед интеграцией нужен фактический 200/DTO на `evrasia.rest` и подтверждённый production rollout.

**Итоговый статус миграции:** этот публичный метод добавляется как одна из 33 известных бизнес-функций в машинную карту замещения V4. Это **не** означает, что остальные 62 объявления V4 уже перенесены. V4 остаётся действующим, пока не переведены реальные клиенты и не выполнены все критерии sunset.

**Production-раскатка:** подготовлен отдельный безопасный [V5-only guarded installer](SAMZABERU_V5_PUBLIC_REGISTRATION_ROLLOUT_2026-10-23.md), который проверяет реальный `evrasia.rest`, сохраняет backup и выполняет условный rollback при сбое. **Не запущен**, доступность V5 URL снаружи пока НЕ подтверждена.

## Публичный метод реально принят на основном evrasia.rest

23 октября 2026 исправленный production V5-only installer `FINAL_STATUS=PASS`; GET юридических документов/регистрации HTTP 200 на native Bitrix; отдельная внешняя проверка [GitHub Actions #39999984588](https://github.com/juvantusik/Evrasia_AI_bot/actions/runs/39999984588) подтвердила те же **GET /api/v5/legal/consents** и **GET /api/v5/legal/registration-documents** HTTP 200 по `https://evrasia.rest` с независимым DNS/TLS. Совпадают 3 текущих Bitrix документа, 2 обязательных. **Статус именно GET registration-documents: production deployed + external HTTP accepted.** Валидация POST `/legal/consents/validate` принята на origin, но внешний POST не тестировался. Приватная авторизация V5 выключена. [Отчёт](SAMZABERU_V5_EVRASIA_REST_EXTERNAL_ACCEPTANCE_2026-10-23.md).
