4. Согласованная бизнес-логика ВХОДА после проверенных пароля и статуса:
   А) Текущий server-verified STRONG trusted_device с действующим trust_token, привязкой USER_ID+device_id+platform, неизменённой версией/epoch, ранее пройденным полноценным MFA, без истечения или отзыва → сразу сильная V5-сессия, БЕЗ TOTP/SMS ДАЖЕ когда TOTP включён.
   Б) Нет действующего сильного доверия, а TOTP активен → native Bitrix TOTP challenge, НИКАКОГО автоматического SMS fallback.
   В) Нет действующего доверия/TOTP и native policy ДОКАЗАННО разрешает SMS → SMS challenge только на подтверждённый номер Bitrix; не на введённый клиентом номер.
   Г) Неизвестные/опасные состояния → FAIL CLOSED, без JWT, без платного SMS.
   Строки TrustedDevice V4, полученные исключительно по паролю, не могут сами по себе дать V5 strong enrollment. device_id = sz_ + 64 lower-hex, platform ios/android; device_id сам по себе не удостоверяет устройство.
   После действительной сильной V5-сессии PIN списания должен показываться без ещё одного SMS при серверной проверке текущих assurance/epoch.
